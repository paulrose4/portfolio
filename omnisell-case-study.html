Golden Workflow

黄金缺货闭环

演示从合成 Amazon 事实开始，到受控建议、独立审批、幂等执行凭证和重新同步验证结束。模型参与解释，不拥有任何业务写入权。

01

同步事实并发现 Issue

tenant-scoped connector 导入 Golden Mock 数据，确定性库存算法计算 days of supply、reorder point 和建议补货量。

02

Advisor 组织证据

Operations Brief Advisor 输出严格 Schema，显式携带引用、置信度、缺失数据和新鲜度，但不能修改库存或金额。

03

生成不可变审批计划

计划绑定 tenant、connection、marketplace、Issue、Action、evidence、policy version 与 action hash。

04

独立审批与幂等执行

高风险动作要求独立或双人审批；执行端只接受 approval_request_id、Idempotency-Key 和非业务备注。

05

重新同步并确定性验收

事件消费后重新同步事实，由规则确认 Issue resolved、Execution verified 和 Work Item completed。

System Boundaries

确定性代码负责什么

OmniSell 的核心判断不是“让 Agent 更自主”，而是明确哪些能力绝不能交给不确定模型。金额、库存、身份、授权、策略、审批和状态迁移始终由可测试代码决定。

Deterministic Core

业务事实与规则

Decimal 金额、ISO 4217 币种、UTC 时间、库存、利润、费用、定价规则和状态机。

Bounded Advisor

解释与建议

四类 Advisor 负责 Operations Brief、Customer Case、Listing Optimization 和 Reconciliation 的证据组织与任务草稿。

Safety Control Plane

授权与执行

PostgreSQL RLS、RBAC、Policy、HITL、action hash、幂等、审计、失败恢复和跨租户拒绝。

模型不可越界

LLM 不能选择 tenant、降低风险等级、批准动作、拼接写入参数或把 Mock/导入数据声明为已验证 Amazon 数据。证据不足、Schema 失败或策略拒绝时，系统降级或转人工。

Engineering Incidents

两个比技术栈更重要的复盘

01

“批准 A、执行 B”

旧执行接口仍允许客户端提交 action_type 和 quantity，理论上可能篡改已批准内容。修复后，服务器从不可变 approved plan 重建命令，并校验 action hash、审批独立性、过期状态、连接、策略和唯一执行权。

02

Schema Repair 成功仍判定 no-go

四个受控真实模型案例最终都返回结构化结果，但首次 Schema 成功率为 0%，Schema Repair 率为 100%，端到端延迟约 35.8 至 89.3 秒。系统因此没有把“最终可解析”包装成质量通过。

Verification Evidence

验证证据

770+自动化测试

最近一次带日期结果为 776 passed、10 skipped、0 failed。

4OIDC 角色 E2E

Owner、Operator、Approver 与 Reviewer 的受控浏览器路径。

RLS多租户数据库边界

PostgreSQL 16、non-owner role、Alembic 与 schema fingerprint。

CI供应链门禁

SBOM、Trivy、Gitleaks、迁移检查、前端与 Agent eval 进入流水线。

证据解释

自动化结果证明工程控制路径，不代表 Amazon 业务收益。fixed-fixture 只证明评测器和契约，真实 provider 的首次 Schema 成功率、延迟、Token 和成本需要新的 30 至 50 案例评测。

Known Boundaries

已知边界

01

真实 Amazon 写入仍关闭

当前发布姿态是 read-only pilot。退款、支付逆转、自主取消和跨租户操作继续阻断。

02

业务 KPI 尚未外部验证

没有把合成数据推导为销售额、节省工时、准确率或自动解决率；这些指标需要 2 至 4 周具名只读 Pilot。

03

真实模型质量仍是 no-go

必须用固定模型版本、Prompt、超时和数据集重新完成受控批量评测，才能升级 provider 质量结论。

What This Project Demonstrates

把 Agent 放进真实业务约束

OmniSell 展示的是 Agent Runtime、全栈交付、安全治理和工程判断：模型能做什么、模型不能做什么，以及系统如何用证据证明它没有越界。
